# Training TRACE

The public entry point trains the complete method through two serialized policy
types: `streaming_act` (ACT) and `prism_diffusion` (Diffusion Policy).

```bash
python scripts/train_policy.py --policy streaming_act \
  --defaults-path configs/trace_act.yaml --dataset data/local/task_trace

python scripts/train_policy.py --policy prism_diffusion \
  --defaults-path configs/trace_diffusion.yaml --dataset data/local/task_trace
```

Prepare signature caches first; see [data preparation](data.md). The public YAML
files specify execution and capacity parameters. Method components are fixed by
the release implementation: path/delta signatures, causal prefix training,
signature-indexed slot memory and the policy adapter.

## Reference recipes

| Setting | ACT | Diffusion |
| --- | --- | --- |
| Seed / split seed | 42 / 42 | 42 / 42 |
| Steps | 100,000 | 100,000 |
| Batch size | 8 | 8 |
| Signature depth / embedding width | 3 / 512 | 3 / 512 |
| Slots / routing hidden width | 4 / 512 | 4 / 512 |
| Prefix budget / stride | 32 / 4 | 32 / 4 |
| Experiment tracking | Disabled | Disabled |

These are portable **reference recipes**, not the archived task-specific runs
behind the paper tables. Adjust the dataset, batch size, capacity and training
budget for your hardware and task. The release does not contain a sweep runner
or component-removal experiments.

## Run artifacts

Keep model configuration, processor state, normalization statistics, dataset
split, seed and code revision together with each checkpoint. Training outputs
are placed below `outputs/train/trace-act` or `outputs/train/trace-diffusion`.
Use the actual run and checkpoint names generated by your execution.

`python scripts/train_policy.py --help` lists supported execution options. An
existing full-method checkpoint must have matching architecture and processor
state. Configurations that disable required method components are unsupported.

## First run

Start with the CPU example to check imports and the memory path. Then run a short
training job on a small local dataset to validate video decoding, features and
split handling before using the full budget. The release validation record
distinguishes synthetic checks from real-data training; it does not claim that
the reference budgets were trained during packaging.
